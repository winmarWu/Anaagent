# AI 项目学习（Project Learning · 报告驱动版）

本 Skill 在遵循 `refer/项目学习方式.md` 三阶段主线的前提下，**以「一份由 Agent 写满的学习报告」为交付物**：用户主要提供**可访问的代码范围**（工作区路径、仓库、或已挂载的文件树）；**分析、归纳、拆解、成文均由 Agent 完成**，不得把填表负担甩给用户。

---

## 一、Skill 目标与角色

| 维度 | 要求 |
|------|------|
| **目标** | 用户读完报告即可**建立对项目的结构认知、文件职责、核心链路与技术选型**；核心路径可照报告顺序深读源码。 |
| **Agent 角色** | **首席分析员 + 报告作者**：主动列举目录与文件、阅读关键源码、产出结构化 Markdown；**不是**「提问清单 + 空模板」生成器。 |
| **用户角色** | 提供仓库/根路径（或说明限制）；可选补充业务背景；**不要求**逐段填写报告空白。 |
| **语言** | 报告主体中文。代码与符号保持原样。示例中的 Python 库须按项目实际栈替换（npm、Go、JVM 等）。 |

---

## 二、三阶段定义（与需求对齐）

### 阶段一：宏观定位 — **深度理解项目整体**

**目的**：吃透项目是干什么的、结构怎样、每一块放什么、目标与输入输出、**核心文件是谁**。

Agent **必须自行产出**（基于可读源码与配置文件，禁止留空表让用户填）：

1. **项目一句话与边界**  
   - 产品/库的定位；典型使用者；**不做什么**（边界）。

2. **目标与输入输出**  
   - **业务/功能目标**（可观测：CLI 参数、HTTP 路由、公开 API、main 入口行为）。  
   - **输入**：配置、请求、文件、环境变量等（列出来源与格式层级即可）。  
   - **输出**：产物、响应、副作用（写库、写文件、发请求）。

3. **目录结构说明**  
   - 树形或分级列表：**每个一级（及重要二级）目录**的职责一句话。  
   - 若仓库极大：允许对深层目录做「模式归纳」（例：`src/components/*` 均为 UI 组件），但须说明依据。

4. **文件级总览**  
   - **每个源码/配置关键文件**至少一行：**路径 + 职责**（配置、入口、领域逻辑、测试、构建等）。  
   - 体量过大时：**先全量路径索引（按类型分组）**，再对「入口 + 核心业务目录」逐文件展开，其余在「附录 · 其余文件索引」中保持一行一职。

5. **核心文件清单（排序 + 理由）**  
   - 按学习优先级 **P1、P2…** 排序。  
   - 每条：**路径 + 为何核心**（调用关系、数据流、配置枢纽、唯一入口等）。  
   - **非核心文件列表**：单列，注明后续只做阶段一（已在总览覆盖）+ 阶段二（文件级），**不做阶段三**。

---

### 阶段二：文件级拆解 — **逐文件掌握符号与入口**

**目的**：对每个要拆解的文件，列出类/函数级信息，标出入口与核心实现纲要；**由 Agent 根据源码填写**。

对 **每一个** 纳入本轮学习的文件（**核心文件全量**；**非核心文件**亦须完成本阶段，但可略写辅助函数），Agent 产出：

1. **文件头摘要**  
   - 路径、在阶段一中的角色、依赖的主要模块/包。

2. **符号表（类 / 函数 / 方法 / 导出名）**  
   - 每个符号：**名称、类型（函数/类/常量等）、可见性（public 等，按语言习惯）、一句话职责**。  
   - **入口函数**（对外 API、`main`、`if __name__`、路由 handler、框架生命周期钩子等）**单独标出「入口」**。  
   - **参数与返回值**：列出**类型或形态**（若类型复杂，用自然语言描述）；可选注「副作用」。

3. **核心函数（Agent 标注 ★，非用户标注）**  
   - Agent 根据：**调用深度、第三方库密度、分支复杂度、是否处于热路径** 选出本文件 **★ 核心函数**（通常 1～5 个，宁少勿滥）。  
   - 对每个 ★：**3～8 条「实现纲要」**（步骤级，不是贴全文）；**关键分支与异常路径**点一句。

4. **非 ★ 函数**  
   - 一行一职即可，不必展开实现。

**禁止**：在阶段二末尾留「请用户用 ★ 标注重点函数」类话术；★ **必须由 Agent 完成**。

---

### 阶段三：函数级拆解 — **仅核心文件，吃到实现与选型**

**目的**：对**核心文件**中的 **★ 函数**（及 Agent 判断必须连带理解的从属函数），讲清逻辑、依赖、选型与替代方案。

**范围**：  
- **仅核心文件**做本阶段；**非核心文件不做阶段三**（已在总纲声明）。  

对每个目标函数，Agent **必须写出**（仍基于可读源码）：

1. **实现步骤**  
   - 编号步骤：输入校验 → 主流程 → IO/调用 → 返回/异常（与真实代码顺序一致）。

2. **技术选型与库**  
   - 列出 **第三方库 / 标准库 / 项目内模块** 的关键调用点。  
   - **为何使用该库或该写法**（性能、生态、与框架集成、历史原因等）；**若看不出来**，写「从代码推断：…」或「可能原因待确认」，**不得编造**。  

3. **库/ API 细节**  
   - 关键类名、函数名、重要参数含义（与理解相关的部分）。

4. **可替代方案**  
   - 至少 **1～2 种**合理替代（别库、别模式、别抽象），各 **一句利弊**。

5. **（可选）Learn Project 提示**  
   - 若适合实验，Agent 可附 **一段可复制的小实验描述或伪代码**，作为附录；**不要求**用户先做完实验才交付本阶段正文。

---

## 三、阶段四与循环（弱化「人工填表」）

`refer/项目学习方式.md` 中的阶段四（逐行校验、口头反向输出）**改为可选强化**：

- Agent 可在报告末尾附 **「自测问答 5～10 条」** 与 **「若只读一处应读哪一段代码」** 索引，帮助用户自评。  
- **不**将阶段四作为交付前置条件；**不**要求用户先口头复盘再给出阶段三内容。

**循环**：  
- 按 **核心文件 P1 → P2 → …** 依次：阶段二（该文件）→ 阶段三（该文件，仅核心）。  
- 非核心文件：仅阶段二（阶段一已在总览中覆盖该文件一行说明时，阶段二可引用总览并展开符号表）。

## 四、工作流（Agent 必须遵守）

### 4.1 启动

1. 确认**代码可访问范围**（工作区根、子路径、或用户粘贴的关键文件）。  
2. **立即开始**用可用工具做 **目录列举 + 读 README/package/依赖/入口文件**（若环境提供 Read / Glob / Grep / 列表目录等，**必须使用**）。  
3. 若完全无法读文件：输出 **《受限说明》** — 已尝试什么、缺什么、请用户**一次性**打包路径或粘贴结构；**仍禁止**输出大段空白模板。

### 4.2 交付形态

- 默认输出 **一篇完整 Markdown《项目学习报告》**，建议结构：

```markdown
# 项目学习报告 · {项目名或目录名}

> 生成说明：基于路径 `...` 可读文件；若有盲区见文末「信息边界」。

## 执行摘要（1 分钟读懂）

## 一、阶段一：宏观定位
### 1.1 项目定位与边界
### 1.2 目标与输入输出
### 1.3 目录结构说明
### 1.4 文件职责总览
### 1.5 核心文件排序与理由
### 1.6 非核心文件范围（仅阶段一+二）

## 二、阶段二：文件级拆解
### 2.{n} {文件路径}
（每文件：符号表 + 入口 + ★核心函数及实现纲要）

## 三、阶段三：函数级拆解（核心文件）
### 3.{n} {文件路径} · {函数名}
（步骤、依赖、选型、替代、可选实验提示）

## 四、（可选）自测与阅读索引

## 信息边界与待确认项
（仅列 Agent 无法从仓库确认的点，不写「请你填写下表」）
```

### 4.3 质量约束（反占位）

| 禁止 | 必须 |
|------|------|
| 大面积「待补充」「请自行填写」「TBD」表格 | 用已读代码与配置写满；确实未知则单列「未读原因/待用户补充材料」 |
| 把 ★ 标注交给用户 | Agent 完成 ★ 与阶段三选题 |
| 未读代码就编造文件/函数 | 标注推断或明确「未打开该文件」 |
| 阶段三对非核心文件展开 | 非核心严格止于阶段二 |

### 4.4 大仓库策略

- **阶段一**：先 **入口 + 依赖清单 + 目录语义**，再分「核心目录逐文件」与「其余索引表」。  
- **阶段二**：核心目录 **逐文件**；非核心 **批量表格式**（路径、职责、主要导出）亦可，但须完整覆盖用户指定范围。  
- **阶段三**：**仅 P1～Pn 核心文件** 的 ★ 函数；函数过多时优先 **调用链上层 + 状态突变点 + 外部 IO 边界**。

## 七、效果预期

- 用户获得 **可直接阅读、少空洞占位** 的长文报告。  
- 核心路径 **函数级可落地**；非核心 **文件级可定位**。  
- 学习顺序与 **核心文件排序** 一致，减少平均用力。

---

## 八、注意事项

- **工具能力**：若运行环境无读文件能力，须在《信息边界》中说明，并给出**最小补充包**（例如压缩目录树 + 入口 5 个文件），而不是甩空白表。  
- **诚实**：不确定写「未验证」；引用代码时给 **文件:行号** 或代码块摘要。  
- **安全**：不执行不可信代码；不将用户密钥写入报告。
